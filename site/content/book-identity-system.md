# The Worker Investor Book Identity System

This document turns the visual-trust brief into durable design rules for the website.

## Positioning

The Worker Investor should feel like:

- serious but not academic;
- modern but not trendy;
- practical but not cheap;
- personal but not amateur;
- literary but still actionable.

The site is not just a landing page. It is a trust infrastructure for a long-running book, archive, and toolkit.

## Core Visual Claim

工资结算劳动，资产保存劳动。

The visual system should make this claim tangible:

- wages become cash flow;
- cash flow becomes allocation;
- allocation becomes assets;
- assets become optionality.

## Visual Tokens

- Background: warm paper, not sterile white.
- Text: near black / warm ivory in dark mode.
- Accent: deep purple or blue-purple as a restrained highlight.
- Secondary: graphite, muted gray, brass/gold.
- Diagrams: black linework with one accent color.
- Texture: subtle paper grain or grid, never heavy decoration.

## Book Object Rules

The book object should always include:

- front cover;
- clear spine;
- interior page or contents preview;
- title readable at thumbnail size;
- bilingual title treatment;
- author name when the final cover is ready.

Do not lock the final print spine width until page count and trim size are known. The current cover is a concept object, not the final production cover.

## Website Rules

The homepage should communicate four things quickly:

1. This is a real book project.
2. The author is building it over time.
3. The book has a usable method, not just ideas.
4. The website will continue after the book is done.

The site should avoid:

- generic AI landing page gloss;
- finance-hype visuals;
- startup dashboard cliches;
- motivational self-help aesthetics;
- overbuilt 3D that makes maintenance difficult.

## Page System

- `Home`: book object, thesis, identity system, resource preview.
- `Book`: table of contents, chapter status, sample excerpt.
- `Resources`: worksheet/toolkit roadmap.
- `Library`: posts, case notes, data notes, build logs.
- `Appendix`: versioned supplements, charts, corrections, reader questions.
- `Cases`: transformation paths.
- `Concepts`: glossary and working language.

## Trust Layer

The site should gradually add:

- author page;
- writing progress;
- version history;
- references;
- sample chapter;
- case library;
- newsletter archive;
- reader feedback later.

The goal is not to look expensive. The goal is to look stable, intentional, and worth returning to.
